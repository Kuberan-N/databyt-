The Aim — What Are We Building and Why?

The Problem (in one sentence)

A CFO paying ₹39,000/month expects an answer within minutes. You're one person. You can't be awake 24/7.

The Solution

An AI support agent that understands DataByt deeply — not a generic chatbot, but a specialist that knows your product, your customers, and can take real actions in your system.

Why Python + Google ADK? ADK (Agent Development Kit) is Google's open-source framework for building AI agents. It handles the plumbing — routing messages, calling functions, managing conversation memory — so you write only the business logic. Python because ADK is most mature in Python, and because the adk web visual UI (which you'll use to debug) is Python-only. You'll also use Python at work if you ever join an AI team.

Chapter 4

The Python You Need — Only This, Nothing More

9 concepts. Each explained with a DataByt example. Master these 9, build the whole agent.

This is NOT a Python course. This is the exact Python used in this build — no more. You don't need loops, classes, inheritance, file I/O, list comprehensions, or anything else that's not listed here.

1. Variables — storing a value

agent.py
status = "overdue"      # stores the text "overdue" and names it "status"
count  = 5             # stores the number 5 and names it "count"
url    = "https://..."  # stores a URL
What this teaches you
= (single equals)means "store this value". It's NOT checking equality (== does that).
No type declarationPython figures out the type automatically. status = "overdue" is already a string — no need to say String status.
Why it mattersYou'll store your Supabase client, your API responses, and your env vars in variables.

2. Dictionaries — the most important data structure in ADK

Every tool you build MUST return a dictionary. The agent reads dictionaries to understand what a tool found. This is the number one thing to understand.

agent.py
# A dictionary is a labeled container — like a form with filled-in fields
result = {"status": "success", "count": 5}

# Reading a value from a dictionary by its label
print(result["count"])   # → prints: 5
print(result["status"])  # → prints: success

# The two dictionaries ALL your tools must return:
# When it worked:
return {"status": "success", "count": 5}
# When it failed:
return {"status": "error", "message": "Could not reach database."}
What this teaches you
{ } curly bracescreate a dictionary
"key": valuea label (string) followed by a colon, then the value. Pairs separated by commas.
result["count"]reads the value stored at label "count"
Why "status" keyADK reads the status key to know if the tool succeeded. Always include it.
Why dictionaries? When your tool runs, the agent receives its return value. The agent reads the dictionary to form its reply. "count: 5" becomes "You have 5 overdue invoices." The agent can't work with raw numbers — it needs labeled data.

3. Functions — reusable named blocks of code

agent.py
def get_invoice_count(status):
    # everything indented here is inside the function
    count = 5           # pretend we looked this up
    return count        # sends the result back to whoever called it

# Calling the function:
result = get_invoice_count("overdue")   # result is now 5
Line by line
defshort for "define". Tells Python you're creating a function.
get_invoice_countthe function's name. Use lowercase with underscores. Verbs preferred.
(status)the parameter — a variable that gets its value when someone calls the function. You can have multiple: (status, org_id)
: (colon)starts the function body. Everything indented below this belongs to the function.
indentation (4 spaces)Python uses indentation (not curly braces) to group code. Wrong indentation = error.
returnsends a value back to whoever called the function and exits it. Without return, the function returns None.

4. Type hints + docstrings — critical for ADK tools

Type hints and docstrings are how ADK tells Gemini what your tool does and what to pass to it. This is the most ADK-specific thing to understand.

agent.py
def get_invoice_count(status: str) -> dict:
    """Returns how many invoices have a given status.

    Args:
        status: One of 'open', 'overdue', or 'paid'.

    Returns:
        A dict with the count of matching invoices.
    """
    fake = {"open": 12, "overdue": 5, "paid": 240}
    return {"status": "success", "count": fake.get(status, 0)}
Line by line — every part matters
status: strtype hint — tells ADK this parameter is a string (text). ADK passes this to Gemini so Gemini knows what to send.
-> dictreturn type hint — says this function returns a dictionary. The arrow is just syntax.
"""..."""docstring — a special string that describes what the function does. ADK gives this to Gemini. Gemini reads it to decide WHEN to call this tool and what to pass. A vague docstring = Gemini misuses the tool.
Args: sectiondocuments each parameter. Gemini reads this to know what values are valid for each argument.
fake.get(status, 0)looks up "status" in the fake dictionary. If it's not there, returns 0 instead of crashing.
The docstring is NOT for you — it's for Gemini. When a customer asks "how many invoices are overdue?", Gemini reads all your tool docstrings and picks the right one. If your docstring says "does stuff with invoices" instead of "returns the count of invoices with a given status", Gemini won't know to use it — or will use it incorrectly.

5. f-strings — inserting variables into text

agent.py
org = "Dinemetrics"
count = 5

# f-string: put f before the quote, use {} to insert variables
message = f"Hello {org}. You have {count} overdue invoices."
# result: "Hello Dinemetrics. You have 5 overdue invoices."

# Also useful in error messages:
return {"status": "error", "message": f"Unknown status: {status}"}
What this teaches you
f"..."the f before the quote makes it an f-string. Without f, {} is just text.
{variable}Python replaces this with the variable's value when the string is created.

6. try/except — handling errors without crashing

Every tool that talks to a database or API must use try/except. If the database is down and your tool crashes (raises an exception), the entire agent dies. Instead, catch the error and return it as a dictionary.

agent.py
def get_invoice_count(status: str, org_id: str) -> dict:
    """..."""
    try:
        # code that might fail (network call, database query)
        result = database.query(status, org_id)
        return {"status": "success", "count": result.count}
    except Exception as e:
        # if ANYTHING goes wrong, we end up here instead of crashing
        return {"status": "error", "message": str(e)}
Line by line
try:run the indented code; watch for errors
except Exception as e:if ANY error occurs, catch it and call it "e". Exception = any kind of error.
str(e)converts the error object to a readable string. Eg: "Connection refused"
why not crashif your tool raises an exception, ADK can't process it. The agent returns nothing. The customer sees a blank reply. Always catch and return an error dict.

7. import — using code from other packages

agent.py
from google.adk.agents import Agent         # get the Agent class from ADK
from google.adk.agents import SequentialAgent # and this one too
import os                                    # the os module (for env vars)
from supabase import create_client           # the Supabase client function
Two forms of import
from X import Yget specifically Y from package X. Use this when you only need specific things.
import Ximport the whole module X. Access things with X.something. eg: os.environ

8. Environment variables — secrets that don't go in the code

.env file
GOOGLE_API_KEY=AIzaSy...
SUPABASE_URL=https://yourproject.supabase.co
SUPABASE_SERVICE_KEY=eyJhbGc...
agent.py
import os

api_key = os.environ["GOOGLE_API_KEY"]    # reads the value from .env
db_url  = os.environ["SUPABASE_URL"]      # reads another value

# ADK reads the .env file automatically when you run adk web.
# You don't need to do anything special — just have the .env in the agent folder.
Why env vars exist
SecurityAPI keys must never be written directly in code. If you commit code to git, the key becomes public. .env files are in .gitignore.
os.environ["KEY"]raises a KeyError if the variable doesn't exist. Use this so you know immediately when a key is missing.

9. Using a class without writing one

Agent, SequentialAgent, and other ADK objects are classes. You use them by creating instances. You do not write the class yourself.

agent.py
# Agent is a class that Google wrote inside the ADK package.
# You create an "instance" of it by calling Agent() with parentheses
# and filling in the parameters.

my_agent = Agent(
    name="support_agent",         # a parameter named "name"
    model="gemini-2.0-flash",      # a parameter named "model"
    instruction="...",             # a parameter named "instruction"
)

# my_agent is now a fully configured agent object.
# You can pass it to sub_agents, or name it root_agent for ADK to run it.
What this teaches you
Agent(...)creates a new instance. Every time you call Agent() you get a fresh, separate agent.
name= model= instruction=these are keyword arguments. Order doesn't matter; the name matters.
You don't write class Agent:Google wrote that. Your job is to configure and combine instances.
That's all the Python you need. Variables, dictionaries, functions, type hints, docstrings, f-strings, try/except, imports, env vars, and using a class. If you understand these 9 things, you can write and understand every line of code in this build.

Agent + Tool — giving the agent the ability to DO something
~30 minutes · fake data first, real data in Milestone 5

An agent with no tools can only chat. A tool lets it call a function and use the result. We give the agent one tool that "looks up" invoice counts (fake data for now).

Stop the server (Ctrl-C). Replace the entire contents of support_agent/agent.py:

support_agent/agent.py — full file
from google.adk.agents import Agent       # same as before


# ─────────────────────────────────────────────────
#  THE TOOL — a plain Python function
#  ADK turns this into something Gemini can call
# ─────────────────────────────────────────────────
def get_invoice_count(status: str) -> dict:
    """Returns how many invoices have a given status.

    Args:
        status: One of 'open', 'overdue', or 'paid'.

    Returns:
        A dict with a 'count' key containing the number of invoices.
    """
    fake_database = {"open": 12, "overdue": 5, "paid": 240}

    if status not in fake_database:
        return {"status": "error", "message": f"Unknown status: {status}"}

    return {"status": "success", "count": fake_database[status]}


# ─────────────────────────────────────────────────
#  THE AGENT — now with a tool
# ─────────────────────────────────────────────────
root_agent = Agent(
    name="support_agent",
    model="gemini-2.0-flash",
    description="DataByt support assistant that can check invoice counts.",
    instruction="""
    You are DataByt's support assistant.
    When asked how many invoices are open, overdue, or paid,
    ALWAYS use the get_invoice_count tool to find the number.
    Never guess a number. Report what the tool returns.
    """,
    tools=[get_invoice_count],   # ← this line gives the agent the tool
)
Every new line explained
def get_invoice_count(status: str) -> dict:defines the tool. It's a plain Python function — no special decorator or ADK class needed. ADK detects it's a tool when you add it to the tools list.
the docstring ("""...""")Gemini reads this to know what the function does and when to call it. The Args section tells Gemini what values to pass for each parameter.
fake_database = {...}a dictionary holding pretend data. Key = status string, Value = count. We replace this with a real database call in Milestone 5.
if status not in fake_database:checks that the status is one we know. If Gemini passes "cancelled" (which we don't handle), we return an error instead of crashing.
tools=[get_invoice_count]a list of functions the agent can call. The square brackets [ ] create a list. You can add more tools here: tools=[tool1, tool2, tool3]. The function name goes WITHOUT parentheses — you're passing the function itself, not calling it.

The key new lines explained
the three Agent() blocks above root_agentthese are the specialists. They are defined as variables (knowledge_agent, account_agent, escalation_agent) but they are NOT named root_agent. ADK only runs root_agent directly — the others are only reached through routing.
description on each specialistthe manager uses the description to decide which specialist to route to. Make each description clearly state what kind of tickets it handles. This is what Gemini reads when deciding.
sub_agents=[knowledge_agent, account_agent, escalation_agent]registers the three specialists as children of the manager. The order doesn't matter — the manager decides routing from the descriptions and its instruction.
"Always route. Never answer a specialist question yourself."without this line, the manager might answer product questions itself (partially). This forces it to always delegate.
Why this structure? One agent with one giant instruction that handles all cases fails — it gets confused, contradicts itself, and gives inconsistent answers. Specialists with narrow, clear instructions stay focused. The manager's only job is routing — it does one thing well.

import os
from supabase import create_client

# create the Supabase client ONCE when the module loads
# (not inside the function, so we don't reconnect on every call)
_supabase = create_client(
    os.environ["SUPABASE_URL"],
    os.environ["SUPABASE_SERVICE_KEY"],
)


def get_invoice_count(status: str, org_id: str) -> dict:
    """Returns how many invoices an organisation has with a given status.

    Args:
        status: One of 'open', 'overdue', or 'paid'.
        org_id: The organisation's unique ID (UUID string).
    """
    try:
        response = (
            _supabase
            .table("invoices")          # which table to query
            .select("id", count="exact") # select id column, get exact count
            .eq("org_id", org_id)        # filter: org_id must match
            .eq("status", status)        # filter: status must match
            .execute()                     # run the query
        )
        return {"status": "success", "count": response.count or 0}
    except Exception as e:
        return {"status": "error", "message": str(e)}
Every new line explained
_supabase = create_client(...)creates a connection to your Supabase database. The leading underscore _ is a Python convention meaning "this is a module-level private variable". We create it once here (not inside the function) so it doesn't reconnect on every call.
os.environ["SUPABASE_URL"]reads the value from the .env file. Raises KeyError immediately if the variable is missing — better than silently getting None.
.table("invoices")picks which database table to query — like FROM invoices in SQL.
.select("id", count="exact")we don't need the actual data, just the count. count="exact" tells Supabase to return the total row count in response.count.
.eq("org_id", org_id)adds a filter: only rows where org_id column equals the org_id parameter. Like WHERE org_id = '...' in SQL.
.eq("status", status)second filter: only rows where status column equals the status parameter.
.execute()actually runs the query. Without this the query is just built, not sent.
response.count or 0response.count is the row count. "or 0" means: if count is None (no rows found), use 0 instead.
try/except Exception as eif the database is unreachable, the query fails, or any other error occurs, we catch it and return a proper error dictionary instead of crashing the agent.

Create this file in your DataByt repo:

src/app/api/support/route.ts — full file
import { NextRequest, NextResponse } from "next/server";

const AGENT_URL = process.env.SUPPORT_AGENT_URL!;  // the Cloud Run URL

export async function POST(req: NextRequest) {
  // 1. Parse the request body
  let body: { message?: string; orgId?: string; ticketId?: string };
  try {
    body = await req.json();
  } catch {
    return NextResponse.json({ error: "Invalid JSON body" }, { status: 400 });
  }

  const { message, orgId, ticketId } = body;
  if (!message) {
    return NextResponse.json({ error: "message is required" }, { status: 400 });
  }

  const sessionId = ticketId ?? crypto.randomUUID();  // one session per ticket
  const userId    = orgId    ?? "anonymous";

  // 2. Create a session (ADK requires a session before running)
  await fetch(
    `${AGENT_URL}/apps/support_agent/users/${userId}/sessions/${sessionId}`,
    { method: "POST", headers: { "Content-Type": "application/json" }, body: "{}" }
  ).catch(() => {});  // ignore error if session already exists

  // 3. Run the agent with the user's message
  const agentResponse = await fetch(`${AGENT_URL}/run`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      app_name:    "support_agent",
      user_id:     userId,
      session_id:  sessionId,
      new_message: { role: "user", parts: [{ text: message }] },
    }),
  });

  if (!agentResponse.ok) {
    return NextResponse.json({ error: "Agent unavailable" }, { status: 502 });
  }

  // 4. Extract the agent's reply text from the events array
  const events = await agentResponse.json();
  const lastEvent = Array.isArray(events) ? events[events.length - 1] : events;
  const replyText =
    lastEvent?.content?.parts
      ?.map((p: { text?: string }) => p.text ?? "")
      .join("") ?? "Sorry, I couldn't generate a reply.";

  return NextResponse.json({ reply: replyText });
}
Every section explained
AGENT_URL constreads from env var. The ! at the end tells TypeScript "this will never be undefined" (you've set it in Vercel).
Step 1: parse bodyreads the JSON body the dashboard sends. try/catch handles malformed JSON — returns 400 instead of crashing.
sessionId / userIdADK needs these to manage conversation memory. Using ticketId as sessionId means the conversation context is preserved if the customer replies again with the same ticketId.
Step 2: create sessionADK requires a session to exist before you can run the agent into it. This POST creates it. .catch(() => {}) silently ignores the error if the session already exists (eg. customer is following up).
Step 3: run the agentsends the message to the agent. app_name must match the agent's name="support_agent". new_message is the customer's message in ADK's format.
Step 4: extract replyADK returns an array of events. The last event's content.parts[].text is the agent's final reply. We join all parts in case the reply was split.
