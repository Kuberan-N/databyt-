0. The Strategy

Customer support is where most solo-founder SaaS dies. A CFO paying ₹39,000/month expects an answer in minutes, not "I'll get back to you." You cannot be awake 24/7 — an AI agent that knows DataByt deeply is your unfair advantage.

The bet: VERTICAL, not horizontal

Zendesk AI and Intercom Fin are horizontal — they know nothing about AR, dunning, QuickBooks OAuth, or your product. Your agent knows DataByt better than any human rep, because it is trained on your docs and your past tickets, and it can take real actions inside your system.

"Let me find that for you"       "Your QuickBooks token expired 14 days
generic · hallucinates            ago — I've flagged it, here's the
knows nothing about AR            2-click reconnect link"

                                  reconnects integrations, then replies

The 70/30 rule

  • 70% of tickets are repetitive ("how do I connect QuickBooks", "where's my data", "an email didn't send") → agent auto-resolves.
  • 30% need you (billing disputes, bugs, angry customers) → agent escalates with full context so your reply takes 2 minutes, not 20.

1. What is Google ADK?

ADK = Agent Development Kit — Google's open-source agent framework. It got official TypeScript support (adk-js) in December 2025. That matters: DataByt is TypeScript, so you keep ONE language across your whole stack.

ConceptWhat it isDataByt example
AgentLLM + instructions + toolsThe "Support Agent"
ToolA function the agent can callgetInvoiceStatus()
Sub-agentSpecialised agent it delegates toClassifier, Resolver
RunnerExecutes an agent turnRuns when a ticket arrives
SessionOne conversation threadOne support ticket
StateMemory within a session"already tried reconnecting"
MemoryKnowledge across sessions"this org always has QB issues"
CallbacksHooks before/after callsLogging, guardrails, cost
Workflow agentsSequential/Parallel/LoopClassify → Retrieve → Resolve
Why ADK for support (LangGraph for collections): ADK has native Gemini/Vertex integration (cheapest on your credits), built-in tool-calling + sessions (less boilerplate), and Google's Agent Engine can host it later. Learning both ADK + LangGraph makes you employable in both ecosystems. You're learning concepts — agents, tools, RAG, memory, eval — which transfer everywhere.

4. Implementation in the Codebase

New tables (Supabase)

-- Tickets
CREATE TABLE support_tickets (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id UUID NOT NULL REFERENCES organizations(id),
  subject TEXT NOT NULL,
  status TEXT DEFAULT 'open',     -- open|resolved|escalated|closed
  category TEXT, severity TEXT,
  resolved_by TEXT,               -- 'agent' | 'human'
  created_at TIMESTAMPTZ DEFAULT now(),
  resolved_at TIMESTAMPTZ, sla_due_at TIMESTAMPTZ
);

-- Knowledge base with embeddings
CREATE EXTENSION IF NOT EXISTS vector;
CREATE TABLE kb_documents (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  title TEXT, content TEXT,
  embedding vector(768),          -- text-embedding-004
  source TEXT, created_at TIMESTAMPTZ DEFAULT now()
);

How to test — the discipline that makes it reliable

1. Golden test set — 30 real CFO questions with expected behaviour:

"How do I connect QuickBooks?"      → auto-resolve, KB answer
"My invoices aren't syncing"        → check integration tool
"I want a refund"                   → escalate to human
"Change my dunning to 5 days"       → KB answer + settings link
"An email bounced, can you resend?" → resendEmail tool

2. Run the eval — for each: correct category? correct resolve-vs-escalate? right answer? right tool?

3. Drive it like a user — submit tickets through the form and reply-to email; watch in Langfuse. A blank reply or wrong tool call is a failure.

The escalation safety net: when confidence is low, it MUST escalate — never guess. A wrong confident answer to a CFO is worse than an honest escalation. Test this path hardest.
